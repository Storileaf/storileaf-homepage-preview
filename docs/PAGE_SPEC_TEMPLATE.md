# StoriLeaf public page design and release record

Copy this for every new marketing, resource, pricing, gifting or book page. Follow the [active design system](PUBLIC_DESIGN_SYSTEM.md), [content gate](CONTENT_GATE.md), and [workflow](WORKFLOW.md).

## Scope, authority and status

Page title and working route

Single primary page job and target reader

Current implementation, if any, and authoritative source

Status as proposed, founder approved, implemented preview, browser verified or production released

What must remain unchanged, and what is explicitly authorised

## Section specification

For each section, record its job, approved exact heading/body/action, visual composition, real image source, target link, expected interactions and responsive order.

Identify shared components versus a deliberate one-off editorial composition.

## Content and factual approval

[Content proposal record](CONTENT_PROPOSAL_TEMPLATE.md) for every substantive copy change

Verification against official private production main and applicable book/package terms

Adjacent-section repetition check, British English, CTA clarity and credible promises

Exact founder approval reference, separate implementation authorisation and final implementation commit

## Reusable styling and states

Newsreader and Manrope roles, spacing/radius tokens, colour/contrast treatment and iconography

Mobile, tablet and desktop layouts with the required nine widths

Hover, active, focus, keyboard, touch, disabled, empty, error, loading and reduced-motion behaviour where relevant

## Imagery and performance

Approved photo and rights/source; alt text, intrinsic dimensions, crop/focal point

Which asset is actually above the fold, lazy versus eager loading and responsive source sizing

Reserve space against CLS. Use skeletons only for genuine asynchronous content.

## Verification and release

Source typecheck, content gate, tests, isolated build and published-root guard

Desktop/mobile screenshots, nine widths, short heights, zoom, touch, screen reader where appropriate

Browser console/hydration errors and CTA destination checks

Approval of any visible differences from the approved homepage baseline

GitHub Pages deployment SHA and verified URL, unresolved blockers and updated handoffs
