The founder explicitly authorised completing P4-05 on 20 October 2026. The starting public head was 483caeef69c0abd03e39c7c49449005f5460b88e. The paragraph keeps its demo-privacy ID and exact approved wording. A native p replaces the Radix Description component, which already rendered a paragraph. No CSS, content ledger, dependency, question, placeholder, focus handler, input limit, dismissal or unsaved-state behaviour changed.

The first candidate, a986f03f30d3c585460067b7fc2f67c868f76ce3, passed 80 source tests but failed the first 320px source dialog browser check. The DOM description value was `demo-privacy radix-_r_l_`, not just `demo-privacy`. Adding the explicit Content reference did not prevent the installed Radix Description from registering its missing generated target. [Failed Writing run 39451756093](https://github.com/Storileaf/storileaf-homepage-preview/actions/runs/39451756093) and its artifact are retained. This was a genuine incomplete runtime repair, not a flaky test to rerun until green. The second candidate removes that registration by using the native paragraph. The strict DOM/AX checks and visual thresholds were not loosened.

The [permanent P4-05 evidence record](../qa/package-4/2026-10-20/p4-05-verification.json) owns hashes, environment, exact run IDs, failed observations, raw semantic excerpts, coverage, inspected captures and retention limits. All 13 revised-candidate workflows completed successfully. The source, content, type, protected-baseline and build checks passed with 80 tests, including five new description contract tests.

[Writing run 39452392812](https://github.com/Storileaf/storileaf-homepage-preview/actions/runs/39452392812) passed all ten widths and 19 additional states. All 180 referenced original PNG hashes were checked and all 60 pixel comparisons were independently recomputed. The maximum changed-pixel ratio was 0.001050221844614368 and maximum measured geometry delta was 0.09375px, within the unchanged 0.01 ratio and 0.15px gates. Eight representative original image pairs were visually inspected, covering 320px empty, 390px typed and keyboard entry, 820/1440px empty, short screens and targeted enlargement. No visual change was found in those inspected pairs.

Every source dialog opening now requires exactly one visible description paragraph, the exact dialog and textarea references, and the unchanged accessible title. Chromium's accessibility tree exposes the privacy text as the description of both the dialog and its labelled answer field. Thirteen opening observations are retained in the full report. The comparison allows only this named improvement over the broken baseline; two broken descriptions, extra IDs, a changed title or changed textarea reference fail. This is not a blanket removal of ARIA parity checks.

Keyboard entry, initial focus, forward/reverse focus trapping, both Close controls, Escape, outside dismissal, trigger focus restoration, scrolling, word counts, clearing, 2000 characters, answer reset and no restoration after reload all passed. Normal/reduced motion, emulated touch, short screens and the affected responsive boundaries were retained. [Assembly run 39452392480](https://github.com/Storileaf/storileaf-homepage-preview/actions/runs/39452392480) passed its full ten-width, 292-capture checkpoint and all ten combined journeys. Its fresh report was inspected, but its images were not independently reviewed again for this narrow fix.

### Coverage limits and remaining acceptance

Writing used Chrome for Testing 155.0.8059.84, Playwright 1.56.1 and Ubuntu 24.04.5. Initial and final runner images differ while the browser executable and harness hashes match; no permanent measurement-stability conclusion is claimed. Touch was emulated and text enlargement was targeted font/line-height doubling. Native zoom, physical devices, other engines and actual screen-reader speech were not tested here. An accessibility-tree description is not evidence of a spoken announcement.

P4-05's source repair and automated verification are complete. Its original screen-reader criterion is still open, so the whole acceptance row is not marked closed. On the isolated corrected build, record the OS, browser, screen reader and verbosity settings; open Try answering a question by keyboard; listen for the question and privacy description; check the answer field's name/description; traverse the controls; close with Escape and verify trigger focus; then reopen and confirm the answer is empty. Investigate missing or inappropriate announcements rather than inferring success from this tree check. The approved question and privacy wording must not be rewritten as part of that test.

The existing P4-06 enlarged heading observation remains unchanged. Ten description warnings in the final quality report belong to the deliberately unchanged published baseline, not the corrected source. Two further entries record the existing enlarged 320px heading extent, one per version. This is not a broad accessibility certification.

## CI consolidation proposal, not implemented

Before the first separately authorised new public page, map duplicate jobs by command, source/ref, inputs, browser and artifacts. Retain one authoritative source/content/types/build/protection validation per candidate and relevant visual suites with verified identities. Reuse artifacts only when their hashes/configuration match. Preserve failures, thresholds, width/state coverage, environment and guard assertions. Measure durations and unreliable measurements before claiming improvement. Do not delete jobs merely because their titles resemble one another. This repair did not consolidate or disable any workflow.
